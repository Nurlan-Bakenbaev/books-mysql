# Путь системного администратора 2026

Интерактивная дорожная карта с 31 уроком в шести этапах: сети и виртуализация, Linux и сервисы, Windows Server, гибридное облако, автоматизация и мониторинг, безопасность и итоговый проект. Каждый шаг содержит самостоятельное объяснение, ссылки на конкретные учебные материалы с подсказками для чтения, лабораторные действия, ожидаемый результат и типичные ошибки. Следующий незавершённый урок предлагается автоматически; существующий прогресс сохраняется.

Библиотека объединяет открытые книги, курсы, документацию и сообщества с указанием языка и условий доступа. Подборка составлена в ноябре 2026 года по открытым материалам, включая Linux Upskill Challenge, документацию Microsoft, Docker, Ansible и Prometheus. Объяснения в приложении написаны самостоятельно; они не являются переводом или копией этих источников. Внешние материалы, тарифы и версии меняются, поэтому сверяйте их с документацией автора. Практику выполняйте в изолированной среде и не публикуйте секреты.

Встроенная читалка PDF.js показывает выбранный на устройстве PDF целиком, с оглавлением, поиском и переходом по страницам. Для ссылок путеводителя откройте свой экземпляр книги Jennifer Davis «Modern System Administration» в читалке. Путеводитель содержит пояснения на русском; оригинал книги — на английском. К каждому из 21 раздела курса добавлены самостоятельные объяснения и учебные примеры, а к соответствующим темам — дополнительные практические уроки дорожной карты. Прогресс, тема и последняя открытая страница сохраняются в браузере на текущем устройстве.

## Разработка

Требуются Node.js и npm. Из каталога `frontend`:

```sh
npm ci
npm run dev
```

Для проверки и сборки:

```sh
npm test
npm run lint
npm run typecheck
npm run build
```

## Развёртывание

Дашборд — статическое приложение: настройте корневой каталог сборки `frontend`, команду установки `npm ci`, команду сборки `npm run build` и каталог публикации `dist`. API и база данных для дашборда не нужны. Для публикации в корне или подкаталоге используется относительный базовый путь Vite. Workflow `.github/workflows/pages.yml` проверяет и собирает приложение при отправке в `main`, а затем публикует `frontend/dist` через GitHub Pages. В настройках репозитория откройте **Settings → Pages → Build and deployment** и выберите **GitHub Actions** в поле **Source**. После смены источника запустите workflow **Build and deploy Pages** через **Actions → Run workflow** для ветки `main`, если автоматический запуск ещё не завершился. Пока выбран вариант Deploy from a branch, Jekyll не публикует собранный дашборд; корневой `_config.yml` только исключает исходники и зависимости из его обхода.
